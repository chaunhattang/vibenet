Technical Architecture Dossier

VibeNet. system & data model

A social media platform — feed, stories, reels, direct messaging, and a Locket-style close-friends moment feed — built on a Spring Boot API and an Expo / React Native universal client.

Backend Java 21 · Spring Boot 4.1 Client Expo 56 · React Native 0.85 Data PostgreSQL + Redis Realtime STOMP / WebSocket
01

System architecture

Four tiers, top to bottom: the universal client talks HTTP + WebSocket to a stateless Spring Boot server, which persists to PostgreSQL and uses Redis for cache, presence, and notification fan-out.

04

Entity catalog by domain

24 entities across six functional domains.

◆ Identity & Social Graph

User

Credentials, role, status, presence (lastActiveAt), refresh token.

Profile

Display name, avatar, cover, bio, gender, DOB. Shares User PK.

Follow

Directed follower → following edge, unique per pair.

Friendship

Bidirectional request with FriendStatus lifecycle.

ProfileVisit

Who viewed whose profile, timestamped.

◆ Feed & Posts

Post

Text + media list, gradient background, share count, owner.

Comment

Threaded (self parent), belongs to post + author.

Reaction

Typed reaction on a post (ReactionType enum).

CommentReaction

Typed reaction on a comment.

SavedPost

Bookmark join, unique per user + post.

◆ Reels & Stories

Reel

Video, thumbnail, duration, audio title, tags, view count.

ReelComment

Comment on a reel.

ReelReaction

Typed reaction on a reel.

SavedReel

Bookmark join, unique per user + reel.

Story

Ephemeral media with expiresAt, media type.

StoryView

View record, unique per story + viewer.

◆ Locket — Close-Friend Moments

CloseFriend

Owner → friend allow-list for moments.

LocketMoment

Photo/video moment, caption, optional reply-to.

LocketMomentRecipient

Per-recipient delivery + viewed state.

LocketReaction

Emoji reaction by a recipient.

◆ Messaging & Notifications

ChatRoom

Deterministic chatId between two users.

ChatMessage

Sender, recipient, text, room reference.

Notification

Recipient + actor + type + related entity, read flag.

DeviceToken

Push + widget token per platform for delivery.

Request & auth flow

Stateless JWT with transparent refresh — the axios client retries once on 401 after silently exchanging the refresh token.

sequenceDiagram
  participant C as Client (axios)
  participant F as JwtAuthFilter
  participant S as Service layer
  participant DB as PostgreSQL
  participant R as Redis
  C->>F: GET /api/posts/feed (Bearer access token)
  F->>F: Validate JWT signature + expiry
  alt token valid
    F->>S: forward authenticated request
    S->>DB: query feed
    S->>R: read/write cache + presence
    S-->>C: 200 { code, message, result }
  else token expired (401)
    F-->>C: 401 Unauthorized
    C->>S: POST /api/auth/refresh (refresh token)
    S-->>C: new access + refresh tokens
    C->>F: retry original request
    F-->>C: 200 result
  end
